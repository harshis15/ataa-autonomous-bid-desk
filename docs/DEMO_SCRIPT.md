# Ataa: five-minute demonstration

1. **Overview (20 seconds):** Ataa helps a proposal engineer turn RFQs into a reviewed bid baseline. Point to Demo/Live AI. Explain whether the current session uses sample responses or Azure.
2. **Scope (50 seconds):** New bid → sample RFQ → Analyse. Show source references, quantities and open questions. Confirm scope. Explain that this shared JSON feeds all paths.
3. **Architect (90 seconds):** Run Architect. Show separate stage events. Inspect the BOM and a source requirement. Open Plant Architecture and click a node. Open Service Hours: 195.8 hours from explicit sample rules, support excluded. The backend computes arithmetic.
4. **Reuse (70 seconds):** In a second bid, show Accelerator's top three. Explain score weights and cabinet/delivery deltas. In a third, show Expert's top five, compare two and choose a lower-ranked reference. These are historical baselines, not newly sized solutions.
5. **Human gate (50 seconds):** Review open items, enter reviewer and decision notes, approve, export. State that reviewer identity is self-attested in the prototype; production requires authentication.
6. **Implementation (20 seconds):** Four prompt tasks; explicit JS orchestration; Azure key stays on the server. Demo mode is repeatable. Production graph retrieval, connectors, RBAC and evaluations are future work.

For a live recording, first configure Azure and run the sample once end to end. Keep the recording honest: if the call fails, show the error and explicitly switch to Demo mode. Do not imply sample results were generated live.
